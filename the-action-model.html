    3. The Action Model

    An action requires information sent by the browser: the URL parameters ([?name=martin&age=42]), form fields, and route parameters. The original course refers to all of this information as the action’s model. This chapter shows how [NestJS] provides it to the action, converts it to the correct type, and validates it.

    import { Controller, DefaultValuePipe, Get, ParseIntPipe, Query } from '@nestjs/common';

@Controller('parameters')
export class ParametersController {
  // /parameters/action01?name=martin
  @Get('action01')
  action01(@Query('name') name: string): string {
    return `name = [${name}], of type ${typeof name}`;
  }

  // /parameters/action02?age=42: a parameter is ALWAYS a string
  @Get('action02')
  action02(@Query('age') age: number): string {
    return `age = [${age}], of type ${typeof age}`;
  }

  // /parameters/action03?age=42: ParseIntPipe converts (or rejects)
  @Get('action03')
  action03(@Query('age', ParseIntPipe) age: number): string {
    return `age = [${age}], of type ${typeof age}`;
  }

  // /parameters/action04?page=2: a default value if the parameter is missing
  @Get('action04')
  action04(@Query('page', new DefaultValuePipe(1), ParseIntPipe) page: number): string {
    return `page = [${page}], of type ${typeof page}`;
  }

  // /parameters/action05?name=martin&age=42: all the parameters at once
  @Get('action05')
  action05(@Query() parameters: Record<string, string>): object {
    return parameters;
  }
}

    Let’s break down this code:

    • Lines 6–9: [@Query('name')] inserts the value of the [name] parameter from URL (the part following [?], called the query string or [query string]);
    • lines 12–15: the parameter [age] is declared as type [number]... but this type is merely a declaration [TypeScript], which is removed at compile time. What we receive is always a string, as shown by the execution;
    • lines 18–21: [ParseIntPipe] is a pipe: an object that transforms (and validates) a parameter’s value before it reaches the action. Here, the string ['42'] becomes the number 42; a non-numeric string causes a 400 (Bad Request) error, without the action being executed;
    • lines 24–27: the pipes are chained together: [DefaultValuePipe(1)] replaces a missing parameter with 1, then [ParseIntPipe] converts it;
    • lines 30–33: [@Query()], without any arguments, injects an object containing all the parameters from URL.

    The quotation marks around URL are necessary when it contains the character [&], which has a specific meaning for the console. Note that:

    • a missing parameter is treated as [undefined];
    • a present parameter is a string, regardless of the declared type;
    • a pipe is used to convert and validate a parameter, and returns a 400 status code if the value is invalid.

    3.2. Example 08: An action template described by a class

    When an action has multiple parameters, they are described by a class, often called [DTO] ([Data Transfer Object]). Each field of the class has validation decorators provided by the [class-validator] library. These are equivalent to the attributes [[Required]], [[Range]]..., etc., of [ASP.NET MVC].

    import { Type } from 'class-transformer';
import { IsEmail, IsIn, IsInt, IsNotEmpty, IsOptional, Length, Max, Min } from 'class-validator';

export class PersonDto {
  @IsNotEmpty({ message: 'the name is required' })
  @Length(2, 20, { message: 'the name must have 2 to 20 characters' })
  name: string;

  @Type(() => Number)
  @IsInt({ message: 'the age must be an integer' })
  @Min(0, { message: 'the age must be positive' })
  @Max(150, { message: 'the age cannot exceed 150' })
  age: number;

  @IsIn(['Mr', 'Mme', 'Melle'], { message: 'unknown title' })
  title: string;

  @IsOptional()
  @IsEmail({}, { message: 'invalid email address' })
  email?: string;
}

    Let’s break down this code:

    • line 1: [@Type] comes from the [class-transformer] library, which converts the received data;
    • line 2: the validation decorators from [class-validator];
    • lines 5–7: the name is required ([@IsNotEmpty]) and must be between 2 and 20 characters long ([@Length]). Each decorator accepts a custom error message;
    • lines 9–13: [@Type(() => Number)] requires the received string to be converted to a number before validation: an integer ([@IsInt]) between 0 and 150 ([@Min], [@Max]);
    • lines 15–16: the title must be one of the values in a list;
    • lines 18–20: the email address is optional ([@IsOptional]); if present, it must be valid ([@IsEmail]).

    import { NestFactory } from '@nestjs/core';
import { ValidationPipe } from '@nestjs/common';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  // automatic validation of ALL action models described by a class
  app.useGlobalPipes(
    new ValidationPipe({
      transform: true, // converts the received strings to the declared types
      whitelist: true, // removes the fields not declared in the class
    }),
  );
  await app.listen(3000);
  console.log('Server started on http://localhost:3000');

    import { Controller, Get, Query } from '@nestjs/common';
import { plainToInstance } from 'class-transformer';
import { validate } from 'class-validator';
import { PersonDto } from './person.dto';

@Controller('persons')
export class PersonsController {
  // no ValidationPipe here: the action receives the RAW parameters and
  // decides itself what to do with the errors
  @Get('action01')
  async action01(@Query() raw: Record<string, string>): Promise<string> {
    // 1. raw object -> PersonDto instance (@Type conversions included)
    const person = plainToInstance(PersonDto, raw);
    // 2. checking the constraints (@IsNotEmpty, @Min...)
    const errors = await validate(person);
    // 3. an HTML page in both cases: no 400 error
    if (errors.length === 0) {
      return `<p>Welcome ${person.title} ${person.name} (${person.age} years old)</p>`;
    }
    const items = errors
      .map((e) => `<li>${e.property}: ${Object.values(e.constraints ?? {}).join(', ')}</li>`)
      .join('');
    return `<p>The form contains errors:</p><ul>${items}</ul>`;
  }
}

    Let’s comment on this code:

    • line 11: the action receives the raw parameters: an object whose fields are all strings;
    • line 13: [plainToInstance] ([class-transformer]) creates an instance of [PersonDto] from the raw object, applying the conversions ([@Type]);
    • line 15: [validate] ([class-validator]) checks all constraints. It returns an error array, which is empty if everything is OK. Each error indicates the problematic field ([property]) and the messages for the violated constraints ([constraints]);
    • lines 17–18: no errors—a welcome page;
    • lines 20–23: otherwise, a page listing the errors. In both cases, the response is a HTML page, with status code 200.

    This is the technique that all forms in the case study will use (see Example 19).

    import { BadRequestException, Injectable, PipeTransform } from '@nestjs/common';

// turns a French date "23/09/2026" into an ISO date "2026-09-23"
@Injectable()
export class DateFrPipe implements PipeTransform<string, string> {
  transform(value: string): string {
    const m = /^(\d{2})\/(\d{2})\/(\d{4})$/.exec(value ?? '');
    if (!m) {
      throw new BadRequestException(`[${value}] is not a date in the dd/mm/yyyy format`);
    }
    const [, day, month, year] = m;
    const iso = `${year}-${month}-${day}`;
    // "31/02/2026" has the right shape, but does not exist
    if (new Date(`${iso}T00:00:00Z`).toISOString().slice(0, 10) !== iso) {
      throw new BadRequestException(`the date [${value}] does not exist`);
    }
    return iso;
  }
}
    • lines 4–5: a pipe is a class [@Injectable()] that implements the interface [PipeTransform<input, output>];
    • line 6: its method [transform] receives the parameter value and returns the transformed value, which will be received by the action;
    • lines 7–9: a value that does not have the form [dd/mm/yyyy] triggers a [BadRequestException] (400);
    • lines 13–15: a date that is in the correct format but does not exist (31/02/2026) is also rejected: [new Date] “corrects” it to 03/03/2026, which is detected.

    import { createParamDecorator, ExecutionContext } from '@nestjs/common';
import { Request } from 'express';

// @Language(): the browser's preferred language, read from the header
// "Accept-Language: fr-FR,fr;q=0.9,en;q=0.8" -> "fr"
export const Language = createParamDecorator((fallback: string | undefined, ctx: ExecutionContext): string => {
  const req = ctx.switchToHttp().getRequest<Request>();
  const header = req.get('accept-language') ?? '';
  const first = header.split(',')[0].trim().slice(0, 2).toLowerCase();
  return first || fallback || 'fr';
});
    • Line 6: [createParamDecorator] creates a parameter decorator, similar to [@Query] or [@Body]. The function receives the decorator’s argument ([@Language('fr')]) and the query’s execution context;
    • line 7: the context provides access to the request [Express];
    • lines 8–10: the first two letters of the header [Accept-Language] are returned, which indicate the user’s preferred languages.

import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  app.useGlobalPipes(
    new ValidationPipe({
      transform: true,
      whitelist: true, // the undeclared fields are removed...
      forbidNonWhitelisted: true, // ... or, with this option, rejected (400)
    }),
  );
  await app.listen(3000);
  console.log('Server started on http://localhost:3000');
}

    3.6.4. Conclusion

    The action template is generated by [NestJS] based on the request: route parameters ([@Param]), URL ([@Query]), the body ([@Body]), and headers ([@Headers]). The pipes convert and validate these values. For a HTML application, it is usually preferable to validate the model yourself (example 09) so that you can redisplay the form.
