    4. The View and Its Model

    Up to this point, actions have generated their own responses. In a MVC application, this is the role of a view: a file that describes the page HTML, with placeholders for the data passed to it by the action—the view’s model. We will use the [Handlebars] view engine via the [hbs] package, which adapts it to [Express].

    Let's comment on this code:

    • Line 9: [{{!-- ... --}}] is a comment ([Handlebars]): it does not appear on the generated page (unlike a comment such as HTML or [<!-- -->]);
    • line 10: a variable missing from the template ([inexistante]) produces an empty string, without an error;
    • lines 12–13: [{{html}}] escapes the special characters in HTML ([<] becomes [&lt;]...): the text is displayed as-is. [{{{{{{html}}}}}}] (three curly braces) is inserted without escaping: it is interpreted as HTML. Triple curly braces are used only for HTML generated by the application, never for user-entered data: a user could inject HTML, or even [JavaScript], into the page (a so-called [XSS] attack);
    • lines 15–19: [{{#if}}] / [{{else}}] / [{{/if}}]: a conditional block. The condition is a value from the template, not an expression: [false], [undefined], [null], [''], [0], and the empty array are false;
    • lines 20–22: [{{#unless}}] is the inverse of [{{#if}}];
    • Lines 26–32: [{{#each}}] repeats its content for each element in an array. Within the block, the context is the current element: [{{{{nom}}}}] is the name of the current product. Special variables are available: [@index] (position starting at 0), [@first], [@last]. [../devise] points to the parent context, [@root.nom] to the root model;
    • line 36: a [{{else}}] within a [{{#each}}] handles the case of an empty array;
    • Lines 39–41: [{{#with}}] changes context; a relative path can also be used (line 42).

    import { NestFactory } from '@nestjs/core';
import { NestExpressApplication } from '@nestjs/platform-express';
import { NextFunction, Request, Response } from 'express';
import * as hbs from 'hbs';
import { dirname, join } from 'path';
import { AppModule } from './app.module';

const RACINE = join(__dirname, '..');

async function bootstrap() {
  const app = await NestFactory.create<NestExpressApplication>(AppModule);

   // 1. Static files: public/css/styles.css is served from /css/styles.css
  app.useStaticAssets(join(RACINE, 'public'));
   // Bootstrap is served directly from node_modules, under /bootstrap/
  app.useStaticAssets(join(dirname(require.resolve('bootstrap/package.json')), 'dist'), { prefix: '/bootstrap/' });

   // 2. Views: views/layout.hbs will be the template for the pages at TOUTES
  app.setBaseViewsDir(join(RACINE, 'views'));
  app.setViewEngine('hbs');
   // 3. Partials: views/partials/xxx.hbs is inserted via {{> xxx}}
  await new Promise<void>((fini) => hbs.registerPartials(join(RACINE, 'views', 'partials'), () => fini()));

   // 4. An Express middleware: what it inserts into res.locals is
   /   / added to the CHAQUE view template
  app.use((req: Request, res: Response, next: NextFunction) => {
    res.locals.chemin = req.path;
    res.locals.annee = new Date().getFullYear();
    next();
  });

  await app.listen(3000);
  console.log('Serveur démarré sur http://localhost:3000');
}

    import { HelperOptions } from 'handlebars';

// the 'hbs' module has no type declarations: we describe which ones we use
interface Hbs {
  registerHelper(nom: string, fonction: (...args: any[]) => unknown): void;
  handlebars: { SafeString: new (html: string) => unknown; escapeExpression(texte: string): string };
}

export function enregistrerHelpers(hbs: Hbs): void {
   // {{capitalized name}}: a simple helper, one argument
  hbs.registerHelper('majuscules', (texte: unknown) => String(texte ?? '').toUpperCase());

   // {{#if (eq a b)}}: used as a sub-expression, enclosed in parentheses
  hbs.registerHelper('eq', (a: unknown, b: unknown) => a === b);

   // {{active path '/products'}}: "active" if the current page is under this path
  hbs.registerHelper('actif', (chemin: unknown, prefixe: unknown) =>
    typeof chemin === 'string' && typeof prefixe === 'string' && chemin.startsWith(prefixe) ? 'active' : '',
  );

   // {{currency amount currency='USD'}}: the DERNIER argument of a helper is always
   // the Handlebars object [options]; options.hash contains the parameters
   // named parameters, and options.data.root the complete page template (including res.locals)
  hbs.registerHelper('monnaie', (montant: unknown, options: HelperOptions) => {
    const devise = options.hash.devise ?? 'EUR';
    const langue = options.data?.root?.lang ?? 'fr-FR';
    return new Intl.NumberFormat(langue, { style: 'currency', currency: devise }).format(Number(montant));
  });

   // {{date when}}: a date in the format of the page's language
  hbs.registerHelper('date', (quand: unknown, options: HelperOptions) => {
    const langue = options.data?.root?.lang ?? 'fr-FR';
    return new Intl.DateTimeFormat(langue, { dateStyle: 'full' }).format(new Date(String(quand)));
  });

   // {{stock badge}}: a helper that generates HTML. SafeString indicates to
   // Handlebars not to PAS escape it; it is then up to the helper to escape
   // the data it inserts (escapeExpression)
  hbs.registerHelper('badge', (stock: unknown) => {
    const n = Number(stock);
    const classe = n > 0 ? 'text-bg-success' : 'text-bg-danger';
    const texte = hbs.handlebars.escapeExpression(n > 0 ? `${n} en stock` : 'épuisé');
    return new hbs.handlebars.SafeString(`<span class="badge ${classe}">${texte}</span>`);
  });
}

export async function validerFormulaire<T extends object>(
  classe: ClassConstructor<T>,
  corps: Record<string, unknown>,

   // 1. received object -> class instance (@Transform / @Type apply)
  const dto = plainToInstance(classe, corps);

  const violations = await validate(dto);
   // 3. Keep the first error message for each field

  return { dto, erreurs };

    4.7.1. Validation by the browser

    The attributes [required], [maxlength], [min], [max], [type="email"]... instruct the browser to validate the form before submitting it: the user is immediately notified via a tooltip, without any round-trip communication with the server. This is the behavior triggered by the “Enable” link ([/inscription?html5=1]), which removes the [novalidate] attribute from the form.

    This validation is a convenience, not a security measure: you can bypass it simply by removing the [required] attribute using the browser’s developer tools, or by sending the request with [curl]. Server-side validation remains essential. That’s why the example disables browser validation by default: to demonstrate how the server works. The case study, however, retains both: the HTML5 attributes for convenience, and server-side validation for security.

    4.8. Example 20: The Post/Redirect/Get Pattern

    When a POST form submits successfully, the action can display a page directly. The problem arises if the user then refreshes that page (F5 key): the browser resubmits the form, and the operation is performed a second time (an order placed twice, an appointment made twice...). The Post / Redirect / Get pattern (PRG) prevents this problem: a successful POST action does not generate a page; instead, it redirects to a GET page. Reloading this page only sends the GET request, which has no effect.

    One detail remains: the GET page must display a message (“the task has been added”), even though this message was generated by the POST action in a different request. It is transmitted in a short-lived cookie, which is read and deleted by the next request: this is a flash message.

    import { NextFunction, Request, Response } from 'express';

const COOKIE_FLASH = 'flash';

// sets a message that will be displayed by the PROCHAINE page, and only once
export function flash(res: Response, message: string): void {
  res.cookie(COOKIE_FLASH, message, { httpOnly: true, sameSite: 'lax', maxAge: 60_000 });
}

// with each request: any message is passed from the cookie to res.locals (and thus
// to the view template), and the cookie is cleared
export function flashMiddleware(req: Request, res: Response, next: NextFunction): void {
  res.locals.flash = req.cookies?.[COOKIE_FLASH] ?? null;
  if (res.locals.flash) {
    res.clearCookie(COOKIE_FLASH);
  }
  next();
}
